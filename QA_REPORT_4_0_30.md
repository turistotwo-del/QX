# QX 4.0.30 — AI Lite CPU timeout patch

Исходная причина: тайм-аут при локальной инференции на CPU (`timed out`), при этом `/health` считал модель доступной. В прежней версии нейросеть получала до 215 допустимых полей и большой текст ТЗ, выход до 1400 токенов.

Исправления:
- У QX Lite теперь компактный список полей, зависящий от вида товара; цитаты проверяются по полному исходному документу.
- Ограничение текста одного запроса, около 2700 символов ТЗ; на длинных документах явно сообщает о неполноте анализа.
- Сокращены генерация JSON до 560 токенов, выдача по краткому вопросу до 280 токенов и фрагменты контракта до 2900 символов.
- Контекст llama.cpp 4096 вместо 8192 и 6 CPU потоков вместо 4.
- Появилась кнопка «Тест ответа AI» с реальной короткой генерацией и временем выполнения.
- Ошибки времени ожидания стали понятнее; прогресс времени показывается, интерфейс не блокируется глобальным overlay.
- Никакие требования не применяются автоматически, исходные данные и цитаты хранятся без изменения.

- `python -m unittest -q modern.test_modern modern.test_337_regression modern.test_peripheral_choice`: 27 пройдены.

- Новый набор регрессий AI Lite: 8 тестов, в составе 282.

## Ограничения
- Настоящую скорость Qwen2.5 GGUF в Windows и загрузку llama.cpp на машине пользователя тестировать в Linux нельзя.
- Ожидание модели может продолжать превышаться на медленных CPU или при перегрузке; тестовый запуск с реальной моделью на Windows остаётся необходимым.
- В режиме Lite проверяется не весь перечень 215+ полей; потребуется ручная проверка сложных ТЗ.
