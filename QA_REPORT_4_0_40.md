# QX 4.0.40 DEV — проверка исправления импорта

Дата: 29 октября 2026 года. Среда: Linux, Python 3.12, TypeScript 5.9.3, Chromium.

## Воспроизведённые причины отказа 4.0.39

- Карточка создавалась в SQLite, но интерфейс ждал завершения всех запросов к сайту — до обновления реестра.
- Неожиданная ошибка источника оставляла карточку в базе, показывая только общий сбой без обновления экрана.
- Отсутствие `defusedxml` в старом Portable runtime приводило к ошибке до создания карточки.
- Часть действительных ссылок на файлы не распознавалась; сессия cookies не сохранялась между обращениями.
- Скопированные ссылки, знак `№` и пробелы отклонялись или обрезались полем ввода.

## Результаты

- Полный pytest: **439 passed**, **113 subtests passed**, 0 failed, два предупреждения библиотек тестирования.
- Штатная компиляция TypeScript, проверка JS, `--eis-selfcheck` и `--selfcheck` — PASS.
- 13 ранее зарегистрированных сценариев Chromium — PASS; новый сценарий фонового импорта — PASS.
  Проверялся фактический код завершения отдельных процессов, не только напечатанные сообщения.
- В браузерной проверке POST фоновой задачи вернул HTTP 202 за десятки миллисекунд,
  пока ответ источника намеренно был заблокирован. Карточка и переход в неё уже были доступны.
- Проверены этапы задачи, повторный клик, переход между разделами, перезагрузка страницы,
  авария источника и частичный комплект с одним сохранённым файлом и одной ошибкой.
- Проверены настоящий SQLite и точные DOCX-байты: ЕИС → официальный адрес карточки → вкладка документов → файл;
  отдельно ЕИС недоступен → вторичный источник → его подписанные поля → документ → SHA-дедупликация.
- Проверены оригиналы DOC/XLS/RTF/RAR/7z: сигнатуры, сохранение без исполнения/распаковки,
  ZIP-пакеты, аудит целостности, резервное копирование, восстановление и удаление.
- Проверен старый runtime без XML-библиотеки: ошибка обнаруживается до повторного использования ready-маркера.

Положительные сетевые ответы в автоматических проверках — контролируемые фикстуры. Новые разметки ЕИС
основаны на опубликованных парсерах; источники и ограничения указаны в `tests/fixtures/eis/SOURCES.md`.
Номер пользователя `0325100013726000029` включён в проверки нормализации и резервного пути,
но тестовые сведения и документ не являются данными этой настоящей закупки.

## Что не подтверждено

Текущая применённая политика облачной среды не разрешает `zakupki.gov.ru`, `zakupki.kontur.ru`
и `files.zakupki.kontur.ru`. Адреса добавлены в черновик, который не применяет себя автоматически.
Живые ответы сайтов и реальные документы указанной закупки в этой среде не получены.
Для такой проверки нужно сохранить сетевые настройки среды и применить/опубликовать её конфигурацию.

Не проверены нативный Windows WebView2, первый Portable-запуск на Windows и работа платных/закрытых сервисов.
Контур используется только как явно обозначенный вторичный публичный источник.
Полнота комплекта ЕИС и доступность закрытых файлов не гарантируются; сборка остаётся **development**.
