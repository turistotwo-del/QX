# QX Подборщик 4.0.25 — Windows Portable (тестовый кандидат)

Основа: предоставленный архив QX 4.0.24. Предыдущие модули подбора, каталоги, тендеры, расчёты, печатные документы и импорт прайсов сохранены.

## Изменения

1. В «Загрузке ТЗ» можно выбрать одновременно несколько файлов DOCX, PDF, XLSX, XLSM, TXT, CSV, MD или добавить файлы в уже открытый проект; перетаскивание также поддерживает набор файлов. Ограничения: 12 файлов, 30 МБ каждый и 75 МБ совокупно.
2. Каждая позиция знает, из какого файла ТЗ она взята. В разделе отображается список документов с переключением и удалением. Исходники и их привязки записываются в `.qxproj` и автосохранение; старые проекты загружаются в режиме совместимости.
3. При добавлении новых ТЗ **не стирается существующая комплектация и ручная цена**. Для пересчёта новых позиций служит стандартная кнопка «Подобрать комплектующие».
4. Просмотр оригинала, список характеристик и заполнение Word-таблиц связаны с выбранным ТЗ. КП и общая себестоимость по-прежнему охватывают все позиции проекта.
5. Реальная локальная AI-проверка ТЗ: Ollama либо GGUF с установленным `llama-cpp-python`. Модель получает извлечённый текст и текущие требования одной позиции, возвращает JSON с предложенными исправлениями и **дословными цитатами**. Предложения по несуществующим полям, неподтверждённым выдержкам, некорректным типам и неподтверждённым числам отклоняются. Исправления вносятся только по выбору пользователя и затем проходят обычный пересчёт QX.
6. В интерфейсе есть поиск доступных моделей, просмотр предложений в таблице, опция запуска AI после загрузки и отдельно «Применить отмеченные». AI не заменяет локальный алгоритм проверки соответствия; наличие подтверждающей цитаты **не гарантирует правильность толкования документа**.
7. Разбор файлов и AI-инференс работают в отдельных потоках от локального HTTP-интерфейса. При недоступности AI обычный разбор продолжает работать.
8. Загрузка из ЕИС остаётся ручной: пользователь загружает исходные файлы самостоятельно, автоматическая интеграция по номеру не нужна.
9. Для желающих использовать GGUF в Windows Portable добавлен опциональный `ВКЛЮЧИТЬ_AI_GGUF.cmd`. Для Ollama нужны отдельная программа и скачанная локальная модель.

## Ограничения

- Это **не готовый проверенный нативный EXE**; в архиве исходники и запуск через `ЗАПУСТИТЬ_QX.cmd`. Первый запуск требует интернет для собственного приватного Python и библиотек, без системной установки Python.
- Модель AI **не включена** в ZIP. Без локальной модели AI-панель не сможет запустить нейросетевую проверку. GGUF-движок и сама модель требуют отдельной установки/скачивания, Ollama — отдельного запуска.
- OCR для сканов PDF без текстового слоя отсутствует. Очень длинные документы подаются модели фрагментами: в этом случае AI помечает, что анализ неполный.
- ТЗ могут содержать противоположные/исключающие условия, варианты комплектации, много разных позиций: решение AI необходимо подтверждать глазами по источнику.
- В данной среде протестированы Python-тесты и Linux Chromium, **но не первый запуск на реальном Windows, установка GGUF, работа с реальной LLM или скачивание модели**.

Инструкция для Windows и AI: `portable/README_PORTABLE_RU.txt`.
