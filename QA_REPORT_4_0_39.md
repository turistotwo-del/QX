## Что проверяет новый сценарий

Реальный локальный API и SQLite, подставляются только ответы внешнего ЕИС:
номер → карточка → XML-поля → документ DOCX → сохранение → повторный запрос без дубликата →
защита ручных значений → скачанный документ в парсер ТЗ → привязка расчёта к той же закупке.
Проверены Enter, повторный клик, неверный номер без сетевого запроса, недоступный источник,
быстрые правки двух полей, раскрывающееся меню, узкий экран 390 px и отсутствие ошибок JavaScript.
При этом обнаружен и исправлен дефект новой связки: передача первого ТЗ из карточки с непустым
лотом сбрасывала выбранный ID и могла создавать вторую закупку. Финальный сценарий проверяет,
что остаётся одна карточка, лот сохраняется, а расчёт связан с её точным ID. После исправления
повторно прошли 35 тестов сохранения и привязки; новый сценарий Chromium завершился успешно.

## Данные и документы

- Точный номер извещения, официальные ссылки и перенаправления; XML с внешними сущностями отклоняется.
- Неоднозначные сведения не превращаются в факты, вручную введённые значения не затираются.
- Время не переносится на несовпадающую вручную указанную дату.
- Частичные загрузки, ограничения размера/времени и повреждённые/HTML-ответы обрабатываются явно.
- Оригиналы DOC/XLS/RTF: API-загрузка/скачивание, ZIP, сигнатуры, SHA-аудит, backup/restore и удаление.
  Они не запускаются и не преобразуются, неподдерживаемый автоматический анализ явно отмечен.
- Очередь сохранения полей: 6 регрессий на настоящем коде JS, включая изменения во время запроса,
  повтор после ошибки, изоляцию карточек и отмену очереди после удаления.
- Настоящий HTTP-сервер Uvicorn: `/api/health`, `/api/boot`, HTML/JS/CSS — HTTP 200;
  возвращается версия 4.0.39, проверена остановка сервера.

Успех тестовых сетевых сценариев не означает проверку актуального формата живой карточки ЕИС.
Не проверены реальные закупки, авторизация, закрытые файлы и полнота документации.
Поддерживается получение открытых проверяемых сведений; ЕИС может требовать ручного доступа.
