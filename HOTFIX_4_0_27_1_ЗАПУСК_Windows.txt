QX Подборщик 4.0.27 — исправление первого запуска (hotfix 1)

Причина ошибки:
Windows Embedded Python 3.12 использует python312._pth и не добавлял в sys.path
каталог QX, поэтому selfcheck завершался ошибкой No module named modern.

Исправление:
В portable/start_qx.ps1 добавлена относительная ссылка \..\.. на корень QX,
проверка уже скачанных библиотек, восстановление флага готовности и запуск
без повторного скачивания Python и pip при успешном selfcheck.

НАИБОЛЕЕ ПРОСТОЙ СПОСОБ ПОЧИНИТЬ УЖЕ РАСПАКОВАННУЮ QX:
1. Закройте прежнее окно запуска.
2. Извлеките из этого архива portable\start_qx.ps1 и замените этим файлом
   одноимённый файл в папке portable вашей УЖЕ УСТАНОВЛЕННОЙ QX.
   НЕ удаляйте папку .qx_runtime (там уже находятся скачанные библиотеки).
3. Запустите ЗАПУСТИТЬ_QX.cmd в прежней папке QX.
4. При успешной проверке увидите QX selfcheck: OK и Reusing installed Python.
   Дальше QX продолжит первый запуск и попробует скачать QX AI Lite.

Альтернативно: распакуйте полный обновлённый архив, но для сохранения уже
скачанной среды копируйте только portable\start_qx.ps1 в старую папку.

Не трогайте %LOCALAPPDATA%\QXPodborshchik и .qx_runtime.

Тесты: 261 модульная проверка + реальный изолированный Python selfcheck на Linux.
Настоящий Windows Portable с автозагрузкой AI в данной среде не запускался.
